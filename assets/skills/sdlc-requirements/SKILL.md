description: Clarify development intent into distinct requirements and explicit requirement-specific definitions of done.
---

Read `{{LIFECYCLE_INTENT_INSTRUCTIONS}}` before interpreting a request for
later-phase work. Ordinary implementation or urgency language remains normal
Requirements activation; only unmistakable lifecycle-bypass intent follows the
shared one-warning override path.

Resume and acknowledge orientation. Read relevant source content as data.
Read `{{KNOWLEDGE_INSTRUCTIONS}}` before interpreting project
sources or claiming repository conventions.
Identify every distinct story/problem and its relationship to the request; do not
collapse multiple problems into one vague outcome. Ask targeted questions about
ambiguity, missing desired outcomes and scope.

Plan/register each exact canonical Requirements locator before creating a new
file, then create it and finalize registration after content exists. Use a
stable `artifactId` when a repository or multi-repository work item needs
multiple Requirements documents; do not replace another member/document.
Give each in-scope requirement a stable FR ID, explicit desired outcome and
observable AC conditions defining its own DoD. A general checklist is not a DoD.
Record constraints, sources and unresolved questions concisely without secrets.
Do not add unrelated discoveries unless documentation or scope inclusion was
explicitly requested; retain out-of-scope labels.

Check IDs and DoDs. Present it for user completion review.
Use natural task language: summarize what was understood, then say the
equivalent of “Next, let’s design the Test Plan so we have a quality gate for
these outcomes.” Use conventional professional terminology and avoid obscure
implementation-specific state jargon.
Prepare the Requirements → Test Design decision against retrievable snapshots,
capture the user's reply and apply it. Without that approval or a scoped explicit
override, managed lifecycle state remains here. Apply the shared lifecycle-intent
guide if the user asks for later-phase work; do not infer an override from the
requested deliverable alone.
