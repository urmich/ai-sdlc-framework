name: sdlc-technical-design
description: Design the approved solution and its test impact without implementation, then obtain explicit Coding authorization.
---

Read `{{LIFECYCLE_INTENT_INSTRUCTIONS}}` before interpreting implementation
language. “Implement this,” “start coding,” urgency, and delivery goals do not
skip Technical Design; only unmistakable lifecycle-bypass intent follows the
shared one-warning override path.

Resume, read the approved requirements/Test Plan and acknowledge orientation.
Read `{{KNOWLEDGE_INSTRUCTIONS}}` and `{{BUILDING_INSTRUCTIONS}}` before
selecting components, toolchains, build
boundaries, or operational prerequisites.
Describe the proposed components, boundaries, state contracts, interfaces,
failure behavior, concurrency, compatibility, information protection and
operational prerequisites. Resolve actual APIs/tool capabilities rather than
inventing methods, defaults, pipelines or environments.

Map the solution to requirements and tests. Keep modules cohesive and complexity
proportionate. Expose uncertainty and alternatives that matter to the user.
Automatically maintain in-scope earlier documents and report each logical batch;
do not redefine out-of-scope work or treat maintenance as new approval.
Add new test needs to the living plan.

By default, produce no implementation, test code or runnable prototype in this
phase. Apply the shared lifecycle-intent guide if the user explicitly bypasses
this boundary; never treat ordinary implementation language as approval or an
override event.
Plan/register each exact Technical Design locator before creating a new file,
using stable `artifactId` values for multiple member/design documents.
finalize registration after content exists, evaluate structural conformance and present completion for
user review. Explain once, in task-specific language, that the next step is to
implement and validate the agreed design. Prepare the Technical Design → Coding decision with retrievable
snapshots of the canonical artifacts. Apply only a matching captured response
or the user's explicit scoped override.
