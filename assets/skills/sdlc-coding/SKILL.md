Read `{{LIFECYCLE_INTENT_INSTRUCTIONS}}` before interpreting a Coding request
that arrives before its prerequisites. Ordinary implementation/fix/urgency
language returns to the applicable current stage and begins useful work there;
only unmistakable lifecycle-bypass intent follows the shared one-warning
override path.

Resume, load relevant requirements/Test Plan/design and acknowledge orientation.
These are managed-lifecycle recommendations, not execution locks. A genuine
stage override proceeds through normal host permissions without waiting for a
phase record, while remaining truthfully unmanaged. Non-stage controls remain
applicable.
Read `{{KNOWLEDGE_INSTRUCTIONS}}`, `{{CODING_INSTRUCTIONS}}`, and
`{{BUILDING_INSTRUCTIONS}}` before implementation. Read
`{{TESTING_INSTRUCTIONS}}` before changing or running tests, and
`{{REVIEWING_INSTRUCTIONS}}` before Review. Apply compatible
project-specific rules first. Implement focused increments and planned tests.
Verify APIs, keep documents aligned, and notify changes.

After every implementation/test/configuration fix, create a current candidate
validation cycle and reset current test projections to NotRun. Run the full local
unit suite first, then every other required local check. Preserve prior results as
historical. No automatic DEV-specific build, deployment or test after a fix.
Multiple locally validated fixes may precede one authorized DEV attempt.

After local success, direct the user to GitHub Copilot CLI `/review`. Use that
built-in review agent's findings rather than substituting self-review or a custom
review skill. Introduce it naturally as the final candidate quality check before
publication or DEV using conventional professional terminology. Resolve blocking findings through Coding; every resulting fix
restarts unit-first local validation and `/review`. Apply its outcome only through
a captured receipt-bound `review-result` decision. A clean result also records
Review completion; the same response may grant candidate/cycle/configuration/
target-bound DEV authorization. Before each remote
operation check external access, push authority, implicit pipeline stages and
conditional PR requirements. PR publication itself needs explicit authority;
its own validation must not depend on a previous passing validation.

For managed tracking, prepare the exact operation and correlation key, mark
dispatching, invoke the provider tool, then record its actual result. A
user-directed call without that bookkeeping proceeds as unmanaged. Reuse a
matching available artifact or matching running build; never describe an
unqualified "latest" as verified. Pin build, artifact and deployment identity.
Timeouts/missing handles remain uncertain until read reconciliation.

Within the authorized DEV attempt, build/reuse, deploy and execute DEV tests without
per-job prompts. A live DEV test from a local host remains DEV. Monitor every run
through a capable host scheduler at 60-second intervals with verified provider
links, origin-aware updates and terminal notices. A stopped monitor is not active.

Obtain current DEV completion before recommending STAGING. Capture STAGING consent before
its build/deployment; one response may confirm DEV and authorize STAGING. After
deployment, follow the configured STAGING owner/location or an exact authorized fallback;
provide a user handoff only when that effective policy selects the user, and
record deployment/artifact/cycle/spec-bound actual results without inventing a
pass. Do not assume development-host access.

After confirmed STAGING success, evaluate current required PR validation and separate
provider-review/merge/artifact prerequisites. Framework `/review` does not satisfy
provider approvals, and provider approval does not replace current candidate
Review. Recommend PROD or the missing prerequisites; never automatically queue
PROD. A fix from any environment returns to local units and `/review`, not a
remote-only retry, and old-cycle consent is not reusable.

Report accurate NotRun/Passed/Failed outcomes, blocked capabilities and conformance
deviations. Use complete audit trailers in meaningful commits when authorized.
The local framework CLI does not commit, push, access providers or deploy for you.
